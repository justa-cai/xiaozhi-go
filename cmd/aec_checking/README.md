# 音频AEC功能检测工具

这个Go程序用于检测电脑是否自带了AEC（Acoustic Echo Cancellation，声学回声消除）功能。

## 功能特性

- 🔍 检测音频设备的基本信息（采样率、声道数等）
- ⏱️ 测量音频系统的延迟
- 🎙️ 分析AEC支持情况
- 🔊 检测噪声抑制和自动增益控制
- 🗣️ 交互式语音测试模式

## 编译和运行

```bash
go build -o aec_checking ./cmd/aec_checking
```

## 检测原理

### 核心检测方法论

本程序采用多层次检测方法来评估系统的AEC能力：

#### 1. 音频延迟测量原理
- **往返延迟测试**: 生成1秒440Hz正弦波测试信号，通过音频管理器播放
- **PCM回调监控**: 设置音频数据回调函数，监控从播放到录音的时间差
- **延迟阈值判断**:
  - 延迟 < 200ms: 可能支持硬件AEC ✅
  - 延迟 ≥ 200ms: 不支持硬件AEC ❌

```go
// 延迟测量核心逻辑
startTime := time.Now()  // 记录开始时间
manager.AddPCMDataCallback("latency_test", func(data []int16, size int) {
    if receivedTime.IsZero() {
        receivedTime = time.Now()  // 记录接收时间
        latency := receivedTime.Sub(startTime)
    }
})
```

#### 2. 采样率质量分析
- **高质量阈值**: 16kHz及以上采样率被认为是AEC处理的最低要求
- **音频带宽评估**: 更高采样率通常意味着更好的音频处理能力
- **频率响应范围**: 支持更宽频率范围的系统通常具备更好的AEC算法

#### 3. AEC能力推断算法

**硬件AEC特征识别：**
- 低延迟处理能力（<200ms）
- 高质量音频采样（≥16kHz）
- 双向音频流同时处理能力
- 实时信号处理能力

**检测逻辑流程：**
```
音频初始化 → 延迟测量 → 采样率分析 → 系统特征检测 → AEC能力判定
```

#### 4. 噪声抑制检测原理
- **频谱分析基础**: 现代音频系统通常具备数字信号处理能力
- **降噪算法普及**: 大多数现代音频芯片集成了基本噪声抑制功能
- **驱动层支持**: 通过音频驱动API检测噪声抑制功能可用性

#### 5. 自动增益控制检测
- **动态范围处理**: 检测系统是否支持音频动态范围调整
- **标准化支持**: 大多数音频标准都包含AGC规范
- **实现方式**: 可通过硬件或软件实现

### 详细技术实现

#### 音频信号生成与处理

- **静音阈值分析**: 通过静音检测精度评估音频处理质量
- **实时反馈机制**: 提供用户实时的音频状态反馈

### 检测项目详情

| 检测项目 | 检测方法 | 判定标准 | 可靠度 |
|---------|---------|---------|--------|
| 声学回声消除 (AEC) | 延迟测量 + 采样率分析 | 延迟<200ms 且 采样率≥16kHz | 高 |
| 噪声抑制 | 系统特征检测 | 现代音频系统默认支持 | 中 |
| 自动增益控制 | 驱动API检测 | 主流音频标准支持 | 中 |
| 音频延迟 | 往返延迟测试 | 直接测量结果 | 高 |
| 音频设备信息 | 系统API查询 | 实际设备参数 | 高 |

### 检测局限性

#### 环境因素影响
- **虚拟环境**: Docker/虚拟机可能无法准确反映真实硬件能力
- **音频驱动**: 不同驱动版本可能影响检测结果
- **系统负载**: 高CPU负载可能影响延迟测量准确性

#### 技术约束
- **软件AEC**: 本程序主要检测硬件AEC，软件AEC可能无法识别
- **音频路径**: 复杂的音频路由可能影响延迟测量
- **设备差异**: 不同厂商的AEC实现方式可能不同

### 结果解读指南

#### ✅ 支持AEC的情况
- 延迟较低（<200ms）
- 采样率充足（≥16kHz）
- 系统具备实时音频处理能力
- 建议：可直接用于高质量语音通信

#### ⚠️ 可能支持AEC的情况
- 延迟适中（200-500ms）
- 采样率满足基本要求
- 系统具备基础音频处理能力
- 建议：需要进一步测试，可能需要软件AEC补充

#### ❌ 不支持AEC的情况
- 延迟较高（>500ms）
- 采样率较低（<16kHz）
- 音频处理能力有限
- 建议：使用耳机或启用软件AEC解决方案

## 故障排除

### 常见问题

**Q: 检测显示"不支持AEC"但实际支持？**
A: 可能是驱动问题或虚拟环境限制，建议使用官方驱动。

**Q: 音频延迟测量超时？**
A: 检查音频设备是否正常工作，权限是否足够。

**Q: 交互式测试没有响应？**
A: 确认麦克风权限已授予，设备工作正常。

## 技术实现

程序通过以下方式检测AEC功能：

1. 利用现有的`cmd/client/audio/`音频管理接口
2. 创建测试音频信号并测量往返延迟
3. 分析音频设备特征和系统配置
4. 使用VAD（语音活动检测）进行交互式测试
